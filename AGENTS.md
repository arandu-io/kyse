# Working in this repository

This is kyse, the component library an Arandu view imports to draw a screen. It
is a Go module that is `go get`-ed and never copied, so a change here lands in
every project that draws a button, at the moment they upgrade and not before.
That is the whole difference from working in an application, and it is what the
rules below are for.

Read `.agents/skills/` before writing code. Each skill is a procedure, and the
one you need is named by the situation you are in.

## The gates

Nothing is finished until all six exit zero.

```sh
export GOWORK=off
aru view:build
gofmt -l $(find . -name '*.go' -not -path '*/testdata/*' -not -name '*.kyse.go')
go build ./...
go vet ./...
go test -race ./...
bash tests/test-layout-guard.sh
```

`GOWORK=off` is not a habit borrowed from somewhere else. This checkout usually
sits inside a Go workspace that redirects the framework to a local directory,
and a consumer has no workspace. With it off, the module resolves the published
framework version — which is what CI compiles against, and what somebody's
`go get` will get.

Both filters on `gofmt` are load-bearing. A `.kyse.go` is excluded from the
compiler by a build tag, and `gofmt` is the only tool in the chain that ignores
build tags — without the filter it reports a syntax error on every component.

`aru doctor` is not in the list, and asking for it here is a wasted minute: it
answers "this is not an Arandu project" and exits 1. It reads an application,
and this is a library.

One thing the last gate does that is not your change: `tests/test-layout-guard.sh`
runs `go mod download all` before it measures anything, which adds the sums of
the whole module graph to `go.sum`. It passes and leaves the file modified.
Check what moved before staging it — `git checkout -- go.sum` if those six lines
are all of it.

## What this repository holds

| | measured with |
| --- | --- |
| 37 components, one `.kyse.go` source each | `ls components/*.kyse.go \| wc -l` |
| 37 compiled `.go` beside them, committed | `grep -l '^// Code generated by' components/*.go \| wc -l` |
| 2 hand-written Go files in `components/`: `doc.go` and `page.go` | `grep -L '^// Code generated by' components/*.go \| grep -v '\.kyse\.go'` |
| 1512 icons, one exported function each | `grep -hcE '^func [A-Z]' icons/icons_*.go \| paste -sd+ - \| bc` |
| 1 direct dependency, and it is the framework | `go list -m -f '{{if and (not .Indirect) (not .Main)}}{{.Path}}{{end}}' all` |

Two more packages travel in the same module and neither draws a page. `mailui`
draws the messages an application sends, in tables and inline attributes,
because a stylesheet does not survive a mail client. `fonts` serves the faces a
project vendored and writes the preload links for them.

## What does not exist here

Reaching for one of these is the most common way to waste an afternoon. None of
them is missing by accident; each was considered and refused.

| A model reaches for | What is here instead |
| --- | --- |
| a stylesheet, a `.css` file, a `<style>` block | semantic class names — `btn`, `field`, `card` — whose rules ship with the skeleton. There is no CSS in this repository |
| a `<script>`, an event handler attribute, a `.js` file | delegation on `data-*` attributes, bound once by the view layer's own script. There is no JavaScript in this repository |
| Alpine, `x-data`, `x-on:`, `@click` | nothing. A directive value is a string the browser compiles, and pages are served `script-src 'self'` with no `unsafe-eval`, so it throws rather than runs. A test reads the sources and fails on one |
| npm, a bundler, `package.json` | nothing. A CI step fails if one appears |
| a component registered by name in a map | an exported Go function. The compiler resolves the name and checks the props |
| a `Size` or `Color` prop on an icon | `currentColor` at `1em`, both losing to the stylesheet rule of whatever contains the icon |
| a second dependency | an argument in an issue, first. This module is imported by every project that draws a button, and a second require is a download for all of them |

## The two rules everything else follows from

**A component is an exported Go function taking its own props struct and
returning `template.HTML`.** That is what makes `components.Buton` and
`ButtonProps{Labl: …}` build errors at the line of the view somebody wrote,
instead of a blank space and a 500 in production.

**A component owns markup and nothing else.** No CSS and no script, and no
network, filesystem, exec or migrations either — `arandu.mod.toml` declares
those four `false`. A component that would need one of them is a component that
does not enter: the behaviour belongs in the view layer's script, in the
framework, and the appearance in the stylesheet the project owns.

## Writing code

The sources are `components/*.kyse.go`. The `.go` beside each one is compiled
output, written by `aru view:build` and committed — `go get` has no build step,
so what is in the repository is what every consumer imports.

Comments, identifiers, error messages, test names and the text of a component
are in English.
